Elpis developer workflow benchmark · v0.1

Can the work survive the long session?

A fixed set of developer jobs compares the same model directly and through Elpis—on correctness first, then on continuity and resource use.

PILOT ONLY · 2 tasks × 2 arms · full suite not run
The claim we are testing

Elpis should help an agent finish long, multi-step developer work without losing the important parts.

Primary proofDid the task finish correctly?

Secondary proofWhat happened to time, tokens, context, tools, and failures?

Not being claimedUniversal superiority, model ranking, or real-world productivity.

What the agent has to do

Six families. Two tasks each. The last two are the Elpis stress cases.

2 tasks

Follow the output rule

Return exactly what was requested, with no extra words.

Why it is here

Sanity check. It confirms the runner and scorer before we interpret harder work.

2 tasks

Fix code, touch nothing else

Repair a bug, run tests, and stay inside the allowed file.

Why it is here

Measures useful code work and whether edits remain inspectable.

2 tasks

Find facts in long files

Use the right record, ignore drafts, and say “not found” when needed.

Why it is here

Measures retrieval and resistance to misleading context.

2 tasks

Complete a file workflow

Read data, calculate, write an answer, and validate it.

Why it is here

Measures multi-step tool use rather than one-shot text generation.

2 tasks

Keep one fact through noise

Search a large tool output and use one buried authoritative record.

Why it is here

This is where Elpis context control should matter; the important fact must survive irrelevant output.

2 tasks

Continue after a break

Inspect in phase one, then repair in phase two after a session break.

Why it is here

This tests whether goals and decisions survive beyond one uninterrupted turn.

The dedicated continuity check

30 exact-string probes after a real long-session and restart sequence.

Three groups of ten

Remember the right facts. Reject the made-up ones.

ExactRecall the planted identifier directly.

ParaphraseFind the same fact when the question changes.

The honest boundary

This can show

  • How often each arm completes these fixed jobs.
  • Which failures are task failures versus provider or runner failures.
  • Whether Elpis changes context use or continuity on this suite.

This cannot show yet

  • That Elpis is better for every project or model.
  • That lower context use improves task quality.
  • That the suite represents all real developer work.
